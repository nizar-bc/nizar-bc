## 🏗️ Architecture Mindset

My approach is:

> **Standard First. Custom Last. Business Value Always.**

Before creating customization, I try to understand:

1. What does standard Business Central already provide?
2. Can configuration or process changes solve the requirement?
3. Is there an existing extension point?
4. Can an event or interface be used?
5. Does the customization create long-term technical debt?
6. What is the real business value?

The goal is not simply to make the requirement work.

The goal is to build a solution that remains **maintainable, upgrade-friendly, testable, and aligned with the Business Central platform**.
